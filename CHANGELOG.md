# Changelog

All notable changes to fastprox. Planned work is in [ROADMAP.md](ROADMAP.md).
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Spectral operators: any absolutely symmetric operator on the singular values of a batch of matrices, and any permutation-invariant one on the eigenvalues of symmetric matrices. Examples: the nuclear norm, its ball, the spectral norm and its ball, nonconvex low-rank penalties (SCAD, MCP, $\ell_q$, $\ell_0$, log), the PSD cone, the spectraplex, $-\log\det$.
  - **C:** `fp_op_spectral_check` says whether an operator qualifies. `fp_spectral_jvp` gives the $k \times k$ core of the derivative from $A = U^\top H V$, after `fp_prox` on the spectrum; the caller keeps the decomposition and the matrix products, so the core still needs no LAPACK or BLAS. Ties and zero singular values take their exact limits from the Jacobian of the prox on the spectrum, through one extra JVP per row; near ties take the average of the two limits within $\varepsilon^{1/3}$ of the scale.
  - **Python:** `fp.Spectral(op, kind="svd" | "eigh")`, with `NuclearNorm`, `SpectralNormBall` and `PSD`. `prox`, `prox_from`, `jvp`, `vjp` and `value` use NumPy's `svd`/`eigh`.
  - **PyTorch and JAX:** `fastprox.torch.prox` and `fastprox.jax.prox` take spectral operators, with the decomposition and the matrix products in the framework on the input's device (GPU included) and the $k \times k$ core on the CPU. Gradients reach `x`, `gamma`, and `lam` or `radius` when `NuclearNorm` or `SpectralNormBall` is passed as a class; PyTorch also has forward mode, JAX `jit` and `vmap`.
  - **Tests:** finite differences on matrices with repeated and zero singular values, where autograd through `torch.linalg.svd` gives NaN or a gradient 28–35% off, and Candès et al.'s closed-form divergence.
  - The design and its sources are in docs/spec.md, "Spectral operators".
- One step per row, image or matrix: `fp_prox_steps(op, gamma, x, out, opt, ws)`, with `gamma` of the batch shape (any strides; 0 broadcasts). Each row gets exactly what `fp_prox` gives on it alone with its step, for any thread count. Derivatives after it use each row's step: `fp_jvp`'s `dgamma` moves every step, `fp_vjp`'s `ggamma` is the sum over rows, and a row's own gradient is $\langle g, \partial z/\partial\gamma \rangle$ over that row from `fp_jvp` with `dgamma = 1`. In Python, `prox` takes `gamma` as an array that broadcasts to the batch shape. So do `fastprox.torch.prox` and `fastprox.jax.prox`, where each step's gradient is its rows' $\langle g, \partial z/\partial\gamma \rangle$, from one more JVP, summed back to `gamma`'s shape; PyTorch's forward mode takes a tangent per step, and spectral operators take one step per matrix. `tests/python/test_steps.py` checks every operator against row-by-row calls, for the prox, the JVP, the VJP and with several thread counts. `test_torch.py` and `test_jax.py` check the wrappers' per-row gradients against finite differences for every shared case.
- The device API of the GPU backend, which has no kernels yet: `FP_DEVICE_CUDA` (DLPack's value 2) and the status `FP_EDEVICE`. The C library loads the CUDA plugin, `libfastprox_cuda`, on first use. It looks first at the path in `FASTPROX_CUDA_PLUGIN`, then next to the library, then on the system's search path, and takes the plugin only from the same version. Arrays on a device still return `FP_EINVAL`. New functions, which already work on the CPU:
  - `fp_device_available` and `fp_op_device_check`. The latter also reports whether one row of an operator is limited to one thread.
  - `fp_workspace_info`: the `fp_info` and status of the last prox call on a workspace.
  - `fp_vjp_device`: `fp_vjp` with the step's gradient in a 0-d array.
  - `fp_workspace_set_stream` and `fp_workspace_get_stream`, for device workspaces.
  - Tests: CTest runs the loader against a stub plugin, a plugin of another version, a missing one and an empty `FASTPROX_CUDA_PLUGIN`.

### Fixed

- Derivatives at a zero threshold (audit K1): where the threshold is 0 (λ = 0, a zero weight or group weight, or γ = 0) the map is the identity, but at x = 0 the Jacobian was 0, so an unpenalised coefficient starting at 0, as in unrolled ISTA, got no gradient. It is now 1 (1/(1 + γ l2) for the elastic net) for soft thresholding, the elastic net, ℓ1 over a box, ℓ0, SCAD, MCP, the log penalty, group ℓ2, the tree-structured norms, and the group SCAD and MCP that use the scalar maps at x_g = 0; `jacobian_diag` now agrees with the empty kink mask there. The log penalty at γλ = 0 also gives the same parameter derivatives whether or not a branch override is set. Tested in `tests/python/test_kinks.py` and by two new cases in `derivative_cases` with an exact 0 in x.
- PyTorch: second-order reverse mode through `fastprox.torch.prox`, `prox_conj`, `tv_iso` and `tv_aniso` (`create_graph=True`, as in `torch.autograd.functional.hvp` and `hessian`) returned a wrong Hessian with no error: torch 2.14's `once_differentiable` no longer refuses double backward, and the prox's own second derivatives were dropped. For soft thresholding the Hessian diagonal was off by 2 on the entries the prox keeps. It now raises `RuntimeError` until exact second order lands in 1.0.x (audit P1). First-order backward and forward mode are unchanged. Tested in `test_torch.py` for soft thresholding, 1D TV, the nuclear norm and both device-native TV functions.
- 1D TV with the ℓ2 norm (since 0.2; also released as 0.5.1): wrong results, and NaN, on rows whose weights or entries span many orders of magnitude. Found by the nightly fuzz run: NaN on entries near 10⁻¹⁴⁷ with only an edge of weight 4·10⁻¹⁴⁹ between them (μ* ≈ 2·10⁻²⁹⁵, in a conjugate prox). Three causes:
  - σx underflowed in the tridiagonal solves, so ‖W D z‖ was 0 at every μ, bisection drove μ to 0, and the zero pivot of a zero weight gave NaN.
  - ‖W D z‖ was computed from differences of z, which carry its rounding: one ulp of z across an edge of weight 0.5 is 10⁻¹⁷, which hid an edge whose part was 10⁻¹⁵⁰. The Newton iteration now runs on the differences, B Dz = μ D x with B = μI + D Dᵀ W² on the edges. B is an M-matrix whose pivots are kept in the same cancellation-free excess form. The step is taken in the normalised dual u/γ. z still comes from one solve with μI + K at the final μ.
  - ‖u₀‖² underflowed for small rows, which passed them as inside. The inside test and the iteration now run on the centred row and γ scaled by a power of two that brings the largest entry to [½, 1). Bisection runs in the exponent, so a root 150 orders of magnitude below its bracket takes a few steps, not 500.

  On such rows the old results were off by up to 100% of max|x|; they now agree with a 700-digit solver to 2·10⁻¹⁶. Ordinary rows change only by rounding, at the same speed. Tested in `tests/python/test_tv1d_l2.py`: the fuzz input against the closed form for two rigid blocks, and scale invariance over 2^±600 for 300 rows with weights over 150 orders of magnitude.

## [0.5.1] — 2026-10-21

A patch release of 0.5.0 on the `release/0.5.x` branch: `pip install fastprox` gets it while 1.0 is a release candidate. The C API, the ABI and the Python API are those of 0.5.0.

### Fixed

- 1D TV with the ℓ2 norm gave wrong results, and sometimes NaN, on rows whose weights span many orders of magnitude, silently: the fix under [Unreleased] above. In tests on random rows, weights over 16 orders of magnitude gave wrong results on three rows in four, by up to 2.5% of max|x|; weights over 8 orders did so only for entries near 10⁻¹⁰⁰.

## [1.0.0rc1] — 2026-10-20

The release candidate for 1.0, on PyPI as a pre-release (`pip install --pre fastprox`). The C ABI is now frozen: until 2.0 it only grows, and CI checks that against the last release. Its ABI is that of 0.5.0, unchanged, under a new major version. The operators and the Python API are those of 0.5.0.

### Added

- An ABI check in CI: the `abi` job compares the C library with the last release using `abidiff` (libabigail), on the types of `fastprox.h`, and fails on any change but an addition. Publishing to PyPI waits for it. CMake now requires `FP_ABI_VERSION` to equal the major version, which is also the soname's. The policy for 1.x is in docs/api.md, "ABI stability".

### Changed

- The major version is 1, and with it `FP_ABI_VERSION` (`fp_abi_version()` returns 1) and the soname: `libfastprox.so.1` on Linux, `libfastprox.1.dylib` on macOS. Programs built against 0.x need rebuilding once, as for any 0.x minor version; no declaration changed since 0.5.0.

### Fixed

- `fp_value`, `Operator.value` and the PyProximal adapter were documented as "since 1.0"; they shipped in 0.5.
- The conda recipe builds the Python package with Ninja. scikit-build-core had picked Makefiles, which conda-forge's Linux image lacks (the GitHub runners have make). Its tests now import the package on the oldest and the newest supported Python, and check the extension with `abi3audit`, as conda-forge's linter suggests.

## [0.5.0] — 2026-10-19

### Added

- A conda-forge recipe, `packaging/conda/recipe.yaml`, for `libfastprox` (the C library, with its pkg-config and CMake files) and `fastprox` (the Python package, abi3). The new `conda` workflow builds and tests it with rattler-build on Linux, macOS and Windows.
- CMake option `FASTPROX_STATIC_LIBSTDCXX`, on by default: it links libstdc++ and libgcc statically on Linux with GCC, as before. conda-forge turns it off, since it provides its own.
- `fastprox.pyproximal.ProxOp`: any operator as a `pyproximal.ProxOperator`, so fastprox works in PyProximal's solvers. It reshapes PyProximal's flat vectors to `dims`, returns $g(x)$ from `Operator.value`, maps `proxdual` to `prox_conj`, and can warm-start the iterative image operators. It is checked against PyProximal's `L1`, its `moreau` test, and a lasso through `ProximalGradient`. The example `examples/pyproximal_tv.py` deblurs an image: the same PSNR as `pyproximal.TV`, about 6× faster. PyProximal (LGPL-3.0) stays optional, in the `interop` dependency group.
- `fp_value` and `Operator.value(x)`: the value $g(x)$, one per row or image, for every operator. The projections give their set's indicator: 0 within a relative tolerance, else infinity. Each value is checked against the operator's prox: $z = \operatorname{prox}_{\gamma g}(x)$ must minimise $g(y) + \lVert y - x \rVert_2^2 / (2\gamma)$ (`tests/python/test_value.py`). This is what the PyProximal adapter needs for its objective, and it is added before the 1.0 freeze.
- A documentation site, https://dvillacis.github.io/fastprox/, built with MkDocs Material from the Markdown in `docs/`, the README, the changelog and roadmap, and the examples (each with its source); the Python reference is generated from the docstrings (mkdocstrings), and formulas are LaTeX, rendered by KaTeX. A workflow builds it strictly on every pull request and deploys it to GitHub Pages on each release.

### Changed

- `fp_op_log` is now `fp_op_log_penalty`, matching the Python `LogPenalty` and leaving no doubt next to `fp_op_log_barrier`: a breaking change to the C API, made before the 1.0 freeze. The Python package is unchanged.

## [0.4.0] — 2026-10-19

### Added

- Kink masks and branch overrides for the box and the nonnegative orthant (entries on a bound), the simplex and the ℓ1 ball (entries at the threshold, on or off the support; for the ℓ1 ball also a row on its sphere, inside or projected) and group ℓ2 (a group at its threshold, zeroed or live), through `fp_workspace_kinks`/`fp_workspace_set_branch` and `ctx.kinks`/`branch=` as for the other operators. Row-level kinks take the side given at the row's or group's first entry. Group ℓ2 now saves its live groups for its derivatives, which are unchanged. Each side matches its one-sided difference (`tests/python/test_kinks.py`).
- Kink masks and branch overrides for tree TV, whose kinks are edges: masks and sides have the shape of x with the last axis over the edges (`fp_workspace_kinks`/`fp_workspace_set_branch` take that shape). An edge with equal ends and its flow on its bound is joined (−1, the default) or kept apart (+1). The fuzzer now covers tree TV.
- The same for graph TV, judged on the flow its solver found, which the prox call now saves with the structure (one double per edge and image); on a graph with cycles the flow is not unique. Graph TV on a forest gives tree TV's kinks and derivatives. The fuzzer now covers graph TV.

### Changed

- Graph TV's max-flow engine is excesses incremental breadth-first search (Goldberg, Hed, Kaplan, Kohli, Tarjan and Werneck, ESA 2015), written from the papers in `src/maxflow/eibfs.hpp`, instead of the Boykov–Kolmogorov engine: 1.9–2.7× faster at γ = 0.5 and 1.2–1.9× at γ = 0.1 on 512² grids, within 12% elsewhere (docs/benchmarks.md). The solutions are unchanged bit for bit (the same cuts); the flow, and with it `info.dual`, the gap to rounding and graph TV's kink masks, can differ.
- A cleared branch override of an image operator (anisotropic, graph and tree TV) copies back the prox call's own structure instead of rebuilding it from the saved x and z, so it is the default bit for bit in float32 too.
- The README describes what sets fastprox apart, with measured figures, and has quick starts for images, PyTorch on GPUs and the C API.

## [0.3.0] — 2026-10-19

Graph and tree TV, PyTorch and JAX wrappers, and image TV on the GPU, with
more accurate and cheaper image TV derivatives, spatially varying weights
for image TV, and kink masks and branch overrides for TV and the nonconvex
maps. The larger open items moved to 0.4 in ROADMAP.md. The C ABI only
grows: every 0.2 declaration and struct is unchanged
(`fp_workspace_set_deriv_tol` now also accepts 0, its new default). The
release candidate 0.3.0rc1 (2026-10-18) had everything below except the
cached reference of `bench/compare_deepinv.py`.

### Added

- A max-flow engine for graph TV (`src/maxflow/`, internal): Boykov–Kolmogorov augmenting paths on two search trees, written from the paper, whose trees and flow carry over between solves when terminal or edge residuals change. It runs in caller memory without allocating and is tested by optimality certificates and against Dinic's algorithm (`tests/c/test_maxflow.cpp`).
- Graph TV, `fp_op_graph_tv(n, m, edges, w)` and `fp.GraphTV(n, edges, weights)` / `fp.graph_tv`: the prox of γ Σ_e w_e |z_u − z_v| on any graph, on the last axis and batched over the others. Parametric max-flow (Chambolle and Darbon; Hochbaum) with each part cut at the mean of its solution, so a part whose cut is trivial ends exactly; every part is cut in one solve per round, reusing the flow and the search trees. Exact to rounding with `tol = 0` (the Python default), else within `tol`·(max x − min x) at every node; `fp_info.gap` is the duality gap with the flow as the dual. Derivatives (JVP, VJP, γ and per-edge weights) are exact averages over the regions where z is constant. Tested by an independent KKT check (`tests/python/test_graph_tv.py`), against 1D TV on chains, anisotropic TV on grids and CVXPY fixtures.
- Tree TV, `fp_op_tree_tv(n, m, edges, w)` and `fp.TreeTV(n, edges, weights)` / `fp.tree_tv`: graph TV for edges that form a forest (trees, paths, in any labelling), exact in one pass by dynamic programming (Kolmogorov, Pock and Rolínek, Algorithm 2), with the breakpoints of the messages in two pairing heaps (O(n log n)) or, when every tree is a path, a sorted deque (O(n)). The gap, the dual and the derivatives are those of graph TV, from code now shared by both (`src/ops/edge_tv.hpp`). 4–8× faster than graph TV on trees; tested against graph TV, against 1D TV on shuffled paths, by the KKT check and CVXPY fixtures (`tests/python/test_tree_tv.py`). `bench/compare_tree_tv.py` times it.
- PyTorch and JAX wrappers, `fastprox.torch.prox`/`prox_conj` and `fastprox.jax.prox`/`prox_conj`: any operator, or an operator class with its parameters, as a differentiable function of the input, the step and the parameters, with the gradients from the library's VJP (and, in PyTorch, its JVP for forward mode). PyTorch: a `torch.autograd.Function`, CPU tensors or a round trip from other devices. JAX: `custom_vjp` over `pure_callback`, under `jit`, `grad` and `vmap`. Tested by `gradcheck` (reverse and forward), `jax.test_util.check_grads` and against the NumPy API on elementwise, row, image, graph and tree operators (`tests/python/test_torch.py`, `test_jax.py`; dependency group `interop`, a CI job on Linux and macOS). `examples/autodiff_frameworks.py` learns TV weights with Adam and γ of isotropic TV under `jax.jit`.
- Device-native image TV, `fastprox.torch.tv_iso`/`tv_aniso` and `fastprox.jax.tv_iso`/`tv_aniso`: the problems of `TVIso` and `TVAniso` solved in tensor operations on the input's device (CUDA, MPS, CPU), with no change to the C API. Forward: FISTA on the dual with the C kernels' step, restarts, gap stopping and warm starts (duals in the C kernels' form, so either side can warm-start the other). Backward in x, γ and the weights: the C kernels' derivatives on the flat regions, found on the device by hooking and pointer jumping and summed by a sort and a segmented scan, so the result is the same run to run (no atomic adds) and memory does not grow with the iterations. PyTorch: reverse and forward mode; JAX: reverse mode under `jit` and `vmap`. Tested in `tests/python/test_device_tv.py` (also on a GPU when one is present); `bench/device_tv.py` times it against the C kernels.
- `bench/compare_deepinv.py`: isotropic TV against DeepInverse's `TVDenoiser` (same problem; Chambolle-Pock with autograd through its iterations): time to a given accuracy on the CPU and the GPU, the host round trip of the C path, and the time, memory and accuracy of the backward. On 8 × 256² images on an Apple M5 Pro, the device path reaches a given accuracy 3–17× sooner on MPS; the unrolled backward keeps 10 MiB per iteration (4 GiB at 400), the implicit one 6 MiB (docs/benchmarks.md).
- One step per image in the device-native image TV: `gamma` in `fastprox.torch.tv_iso`/`tv_aniso` and `fastprox.jax.tv_iso`/`tv_aniso` may be a tensor that broadcasts to the batch shape `x.shape[:-ndim]` (for `x` of shape (B, C, H, W), shape (B, 1) gives each sample its own step), as DeepInverse's denoisers take one σ per sample. Each image matches a call with its own scalar step, and the gradient in `gamma` has `gamma`'s shape. One step for all images runs as before.
- Spatially varying weights for image TV: `fp_op_tv_iso_weighted(ndim, w, alpha)` / `fp.TVIso(ndim, weights, pixel_weights=alpha)`, $\gamma \sum_p \alpha_p \lVert (W D z)_p \rVert_2$ with one weight per pixel, and `fp_op_tv_aniso_weighted(ndim, w, beta)` / `fp.TVAniso(ndim, weights, edge_weights=beta)`, γ Σₐ wₐ Σ_p β_{a,p} |z_{p+eₐ} − z_p| with one weight per pixel and axis, for one image shape (batched over leading axes). The weights enter the dual bounds (anisotropic TV's 1D steps are weighted 1D TV proxes), so the gap, warm starts and the polish carry over, and all-ones weights give the unweighted operator bit for bit. Derivatives in x, γ, w and every spatial weight (`grads.pixel_weights`, `grads.edge_weights`, in the weights' shapes), also through `fastprox.torch.prox` and `fastprox.jax.prox`. Tested against CVXPY fixtures with random weights (some zero), finite differences, adjointness and gradcheck/check_grads (`tests/python/test_tv_spatial.py`, `test_tv_spatial_weights` in `tests/c/test_core.cpp`). `examples/reweighted_tv.py` runs iteratively reweighted ℓ1 for TV^q (Ochs, Dosovitskiy, Brox and Pock 2015) to a stationary point, 6 dB above TV on its test image.
- Spatial weights in the device-native image TV: `pixel_weights` in `fastprox.torch.tv_iso` and `fastprox.jax.tv_iso`, `edge_weights` in `tv_aniso`, the problems of `TVIso(pixel_weights=)` and `TVAniso(edge_weights=)` on the input's device. One map for every image or one per image (the weights broadcast to `x.shape`, edge weights with a leading axis of ndim), differentiable in reverse mode and, in PyTorch, forward mode, with gradients summed back to the weights' shapes. Each image matches the C kernel with its own map, gradients included (to 1e-11, exactly for anisotropic TV); tested by gradcheck, check_grads, `vmap` and on the GPU. 7–12% more time per forward on MPS.
- Kink masks for 1D, anisotropic and isotropic TV (`fp_workspace_kinks`, `ctx.kinks(tol)`): the edges (1D TV: code 1 at the tail; anisotropic TV: bit a for an edge along axis a) and pixels (isotropic TV) where the dual is within `tol` of its bound and the jump or gradient within `tol` of 0, the biactive points where the derivative is set-valued; weights included. Read from the saved solution and dual, the same for any thread count, and checked against the definition recomputed from the returned z and dual. Branch overrides for TV come later (`fp_workspace_set_branch` returns `FP_EINVAL` for them).
- The ties of ℓ0, ℓq and the log penalty are kinks (code 1): masks and branch overrides, with the zero piece on one side and the nonzero branch on the other, as for SCAD and MCP; for the log penalty with γλ ≤ ε², whose map is continuous, the kink where its branch starts. Each side matches its one-sided difference.
- Branch overrides for 1D and anisotropic TV (`fp_workspace_set_branch`, `branch=` in Python): at a kink, side −1 joins the edge's two sides and +1 keeps them apart with the sign of its dual, the two pieces of the B-Jacobian there. Each matches the one-sided difference in a direction that keeps it, in x and in γ, and the VJP is its adjoint. Isotropic TV has none yet.
- `docs/deepinv.md`: `fastprox.torch.tv_iso`/`tv_aniso` in place of DeepInverse's `TVDenoiser`/`TVL1Denoiser`, with the map between their arguments (per-sample steps, stopping, warm starts, gradients) and the differences to expect, checked by `examples/deepinv_tv.py` (needs DeepInverse; it says so and stops without it).
- `bench/compare_deepinv.py` takes `aniso` to compare `tv_aniso` with `TVL1Denoiser`: on 8 × 256² images on an Apple M5 Pro, 2.2–12× faster on MPS to the same accuracy, with a backward of 45–52 ms against 630 ms for 400 unrolled iterations (docs/benchmarks.md).

### Fixed

- 2D anisotropic TV (since 0.2): when ‖x‖² overflowed, as in a conjugate prox at a tiny σ (x/σ ≈ 1e251), the gap target was infinite, the method stopped before its first iteration and returned a z it had never written (left-over memory, so results also changed with the thread count). It now computes z and its gap first. Found by fuzzing the weighted constructors; tested in `tests/c/test_core.cpp`.

### Changed

- Derivatives of isotropic and anisotropic TV read the flat pixels and edges off the dual, in the C kernels and on the device: an entry strictly inside its dual bound, ‖u_p‖ < γ(1 − 10⁻⁹) for isotropic TV and |p_e| < γwₐ(1 − 10⁻⁹) for anisotropic TV, is flat at the solution (complementary slackness). Before, a threshold on the jumps of z set by the certified error, 8·rms(gap), also flattened entries with small true jumps. Isotropic TV's system is stiffer with these entries (pixels on the sphere with small gradients, and more so as the gap shrinks), so its curvature γ/‖g_p‖ is capped at γ/μ, μ = 0.1 w_max √(2 gap / N), a Huber smoothing at the level of the certified error (Hintermüller and Stadler 2006; De los Reyes, Schönlieb and Valkonen 2017) that vanishes with the gap. On 2 × 128² images the isotropic derivative's error against the exact one fell from 18–57% to 4% at a gap tolerance of 1e-6 and from 5–24% to 0.5–0.7% at 1e-8 (near the 0.8% by which two valid derivatives differ at degenerate pixels), at 3–8× the conjugate gradient iterations; the anisotropic C kernel's from 7–19% to 2–5% at 1e-8, and it is exact from 1e-10 or wherever the polish has found the regions; the device's anisotropic derivative is exact at 1e-8. Boundary edges of anisotropic TV take the sign of their dual, as in the polish. The device backward now uses the C kernel's Jacobi preconditioner (1.6–25× fewer iterations than the region sizes alone at γ ≥ 0.1).
- Graph TV on graphs with nodes of high degree: the max-flow engine rescanned all of a node's arcs whenever it grew or was adopted, which made a hub quadratic (a star with 10⁵ leaves took 24.6 s). Nodes of degree above 32 now resume their growth scan and take the first valid parent in cyclic order, and a node freed next to such a hub rejoins its tree after the adoption stage rather than reactivating the hub: 53 ms on that star, 1.7–5× faster on a grid with five hubs, and the same steps as before on graphs without hubs (grids and kNN graphs unchanged). Tested against Dinic's algorithm on stars and random graphs with hubs, fresh and reused (`tests/c/test_maxflow.cpp`).
- Isotropic TV's derivatives stop their conjugate gradients, by default, at the relative error of z that the prox's gap certifies, √(2 gap)/‖x‖ (at most √tol after a solve to `tol`, and no tighter than 1e-10, or 100 ε on the device), instead of a fixed 1e-10 (100 ε in float32 on the device). Residuals below √tol did not change the gradient, whose error after a solve to `tol` is 50–100 √tol, and the C kernel takes 2–5× fewer iterations. A fixed tolerance is still available: `tol` in `TVIso.jvp`/`vjp` (default now `None`), `deriv_tol` in `fastprox.torch.tv_iso` and `fastprox.jax.tv_iso`, and `fp_workspace_set_deriv_tol`, which now takes 0 for the default (its new initial value).
- The device-native image TV sums over regions with a segmented scan in two levels (within blocks of 32 sorted entries, then over the blocks) rather than by doubling over the whole image: 6× faster on MPS for 8 × 512² images, with the same accuracy. With the new stopping rule the isotropic backward on those images takes 137 and 546 ms on MPS at gap tolerances of 1e-4 and 1e-6 (before: 948 and 2494 ms), 269 and 1062 ms with PyTorch on the CPU (1227 and 3282) and 635 and 3111 ms with JAX (5724 and 20 285); on the DeepInverse comparison (8 × 256²) it takes 166 ms at 1e-6 against 612, with the same gradient error (docs/benchmarks.md).
- `bench/compare_deepinv.py` caches its float64 reference in `deepinv_ref_<mode>_<size>_<batch>.npz` (read when present, written otherwise), so that a machine with few cores, such as Colab, can use one computed elsewhere. docs/benchmarks.md has the comparison on an NVIDIA T4.

## [0.2.0] — 2026-10-17

Image operators, nonconvex penalties and more exact operators, with
derivatives. The C ABI only grows: every 0.1 declaration and struct is
unchanged.

### Added

- Anisotropic TV of 2D and 3D images (`fp_op_tv_aniso`, `fastprox.TVAniso`, `fastprox.tv_aniso`): the prox of γ Σₐ wₐ TVₐ on the last 2 or 3 axes, batched over the others. An empty set for the row length returns `FP_EPARAM`.

The new operators are also in `CASES`, the C derivative cases and the fuzzer.

All with derivatives; 0.7–0.9 ns per entry on Apple M5.
- Group Huber, group SCAD and group MCP by norm composition (`fp_op_group_huber`, `fp_op_group_scad`, `fp_op_group_mcp`, `GroupHuber`, `GroupSCAD`, `GroupMCP` and their functions; Beck, Theorem 6.18 and Example 6.66): each group is scaled by the scalar prox of its norm at the step γc_g, with groups and weights as for group ℓ2 and derivatives in x, γ, the scalar parameters and the group weights. The kernel wraps the scalar operator, so its formulas and kink rules are shared. Group SCAD and MCP check a > 1 + γ max c and b > γ max c at call time. Cost is that of group ℓ2 (about 3.5 ns per entry with group ids, 1 ns per entry on rows).
- `tests/python/test_radial.py`: stationarity of the log barrier over 9 orders of magnitude, ℓ1 over a box and the group penalties against minimisation on refined grids, the cone's KKT conditions and polar conjugate, Beck's closed form for group Huber, kink rules, NaN and infinity handling and errors. The new operators are also in `CASES`, the C derivative cases and the fuzzer.
- Tree-structured group norms l₁‖z‖₁ + Σ_g η_g ‖z_g‖₂ for nested or disjoint groups (`fp_op_tree_l2`, `TreeL2`, `tree_soft_threshold`), and the sparse group lasso as the case of a partition (`TreeL2.sparse_group`, `sparse_group_soft_threshold`). The prox composes soft thresholding and the group shrinks from the smallest group up (Bach, Jenatton, Mairal and Obozinski 2012, (3.8)). Groups come as CSR arrays in any order, and the tree condition is checked when the operator is built. Derivatives in x, γ, l₁ and the group weights follow the chain of shrinks. About 1 ns per entry for the sparse group lasso with groups of 16, and 8 ns for a depth-8 tree at n = 10⁶.
- Projection onto the 1D TV ball {Σ wᵢ|zᵢ₊₁ − zᵢ| ≤ α} (`fp_op_tv1d_ball`, `TV1DBall`, `project_tv1d_ball`; Beck 2017, Theorem 6.30). This is the 1D TV prox at the step where the TV equals α. Safeguarded Newton steps find that step: they start from γ = 0⁺, are taken in log–log scale while far from the root, and are exact on the final structure. Derivatives in x, α and the weights come by implicit differentiation of TV(z) = α. It takes 4–15 1D TV solves per row, 40–135 ns per entry on Apple M5.
- 1D TV with the ℓ2 norm of the differences, the prox of γ(Σ wᵢ² (zᵢ₊₁ − zᵢ)²)^½ (`fp_op_tv1d_l2`, `TV1DL2`, `tv1d_l2`). The dual is a trust-region problem. The result is the piecewise mean when the minimal dual, a cumulative sum, lies in the ball. Otherwise Newton's method finds the root of Moré and Sorensen's secular equation, starting from μ = 0 (Nocedal and Wright, Algorithm 4.4). Each of its 2–8 steps costs one tridiagonal factorisation, with pivots kept in a form free of cancellation, and the result is exact to rounding. Derivatives in x, γ and the weights are in closed form, by Sherman–Morrison on the tridiagonal Hessian. 30–90 ns per entry on Apple M5, 1.0–1.3× faster than proxTV's `more_TV2`, which hits its iteration cap and returns wrong results on many large or unscaled rows.
- `tests/python/test_tv1d_l2.py`: agreement with a dense solver near the inside threshold too, with zero weights; an independently built dual point certifying the result up to n = 10⁵; n = 2 against 1D TV; shift, scale and reversal invariance; float32; the γ gradient against finite differences; errors. The operator is also in `CASES`, the C derivative cases and the fuzzer. Fuzzing found two problems. A weight whose square underflows has to count as zero. And each piece has to be centred on its first entry: otherwise the rounding of a constant piece's mean, divided by a tiny w², posed as a huge dual (NaN at w = 2·10⁻⁵³ in the nightly run). `bench/compare_external.py` gains the comparison with proxTV.

  - the projection inequality, special cases and the α gradient against finite differences;
  - errors.

  The new operators are also in `CASES`, the C derivative cases and the fuzzer.

### Changed

- Isotropic TV restarts FISTA when the momentum points uphill (the gradient test of O'Donoghue and Candès 2015), checked every 4th iteration and never at a shorter interval than the previous restart. Solves to a gap of 1e-8 and below take up to 15× fewer iterations (64² noise at γ = 3 to 1e-10: about 26 000 → 1 500). At γ ≤ 0.3, looser solves are unchanged, while at γ = 3 they gain from 1e-4 on. Each iteration costs 1–4% more. Results stay bit-identical for any thread count.
- Anisotropic TV restarts its dual methods when the momentum points uphill (O'Donoghue and Candès), as isotropic TV does; its dual is a quadratic over a polyhedron, so the restarted methods converge linearly. The polish now takes the solution's regions from the dual: an edge whose 1D dual is strictly inside its bound is flat. It runs at the gap checks, tenfold drops of the gap apart, and ends the solve as soon as the polished point meets the tolerance with a gap at most 1/100 of the iterate's. The old polish ran once at the end and took its regions from jumps of z below a threshold, which merged small true jumps and could make the output worse. On 64³ volumes, the time to 1e-6 relative error falls 4.7–5.6× (now 1.8–4.8× faster than proxTV's Yang3 ADMM, which led there), and on 256² and 512² images 2.3–2.8×. Tight solves end at the exact solution to rounding. Some medium accuracies are 2–19% slower. Results stay bit-identical for any thread count, and a warm start from the dual of a polished solve stops at once. The polish needs 3 more doubles per entry of workspace (12 instead of 9).
- `ctx.jacobian_diag(branch=None, kink_tol=0.0)` in Python, the diagonal of dz/dx for the elementwise operators: `jvp(ctx, dx=ones)` under its own name, honouring the branch override. For MCP it gives 0, 1 or b/(b − γwᵢ) per entry, which are the SCD subspaces a semismooth* Newton step reads. Operators whose Jacobian is not diagonal raise `ValueError`. The test over `CASES` checks jvp(ctx, dx) = diag · dx for every elementwise operator.
- Kink masks and branch overrides for soft thresholding, ℓ1 over a box, SCAD and MCP:
  - `fp_workspace_kinks(ws, tol, mask, &count)` reports which entries of a kept prox call lie within `tol` (absolute, in the input's units) of a breakpoint, with a code saying which one. The mask has the new dtype `FP_I8` and is the same for any thread count.
  - `fp_workspace_set_branch(ws, side, tol)` makes `fp_jvp`/`fp_vjp` differentiate the piece on the x − ε (−1) or x + ε (+1) side of each flagged breakpoint, with that piece's formula taken at x. These are the other elements of the B-subdifferential, for example both elements at a biactive entry, and with them each side's derivative matches its one-sided finite difference, in x, γ and θ.
  - In Python: `ctx.kinks(tol)`, and `branch=` and `kink_tol=` on `jvp`/`vjp`.
  - Each map now has explicit pieces, so its default derivatives are bit-identical to before (checked on 64 arrays), and the derivative loops are as fast as before: the override is a separate instantiation.
  - Tests: one-sided differences from both sides at every breakpoint, near-kink entries, the conjugate's units, strides and negative strides, threads, a pass with no allocation, and fuzzing of random overrides.
- `examples/weighted_glasso.py`: the weighted graphical lasso by ADMM. The −log det step is `eigh` plus `LogBarrier` on the eigenvalues, and the penalty step is weighted `Soft` or weighted `MCP` on the packed upper triangle. On 40 variables with 47 true edges and 120 samples, the graphical lasso keeps all but two edges only alongside 28 spurious ones (relative error 0.30). Adaptive weights cut the spurious edges to 6 and miss one more edge (error 0.22), and weighted MCP with the same weights lowers the error to 0.20. The samples are drawn through the Cholesky factor, so they are the same on every platform. The KKT residual of the convex solves is checked, and the Python tests run the example.
- SCAD and MCP take per-entry weights, g(z) = Σ wᵢ ρ(zᵢ): `fp_op_scad(λ, a, weights, out)` and `fp_op_mcp(λ, b, weights, out)` (a new argument, NULL for the unweighted map), `SCAD(lam, a, weights)`, `MCP(lam, b, weights)`, and `weights=` and `axis=` on `scad` and `mcp`. Entry i is the unweighted map at the step γwᵢ (for MCP, wρ_{λ,b} = ρ_{wλ,b/w}). The step condition becomes a > 1 + γ max w or b > γ max w, the rule the group penalties already use. With weights θ = (λ, a or b, w…), and the VJP in w gives the hypergradient for learning, for example, edge weights. Without them θ stays (λ, a or b), and the maps are bit-identical to before at the same speed: the weighted case is a separate instantiation, so the unweighted loop loads no weight. Weighted maps cost about 1.0–1.3 ns per entry on Apple M5. A zero weight, or γ = 0, now returns the entry exactly: MCP's b·|x|/b did not, and its derivative there is now 1.
- The polish of anisotropic TV runs in parallel. Its union-find works in fixed slabs along the first image axis, each joined by its own thread, and then joins the edges between slabs serially. Labels and region sums are also formed per slab. The slabs depend only on the shape, and the output is bit-identical to the serial polish for any thread count. Its edge pass also vectorises now. One polish on a 64³ volume takes 1.8 ms on eight threads instead of 3.9 (6.5 instead of 7.1 on one), and whole solves to 1e-12 are 3–15% faster on eight threads.
- The derivative CG of isotropic TV is preconditioned with the diagonal of the reduced system instead of the region sizes: 1.4–3× fewer iterations in the expensive solves (γ ≥ 0.3, tight tolerances), up to 40% more in cheap ones at small γ. The reported residual keeps its meaning, so `deriv_tol` behaves as before.
- Anisotropic TV in 2D checks its gap on the second block step of each iteration, whose duals are feasible as they stand. A check is then one sweep over the image instead of an extra 1D TV pass, which cost about 60% of an iteration. Checks follow the gap: after iterations 1 and 2, then when its rate of fall predicts the tolerance, and at least every 4 iterations. Before, no solve stopped before iteration 4. A failed polish is retried early only when its ratio to the iterate's gap was at most 1/100 (in 2D, where a polish costs about 1.2 iterations; 3D keeps the eager retries). On 256² and 512² images at λ = 0.1, 1e-2 relative error is reached 1.8–2.0× sooner, now 1.6–1.7× faster than proxTV's DR2, which led there. 1e-3 is up to 22% faster and 1e-6 5–29% faster; 1e-4 at λ = 0.1 is 11–12% slower. The z returned is d − Σₐ qₐ for the dual returned, and the polish depends on the data and the dual alone, so a warm start from the dual of a solve still returns the same bits after 0 iterations. Warm starts also polish from their first check: on nearby images to 1e-6, 1–2 iterations instead of 4–12. `bench/compare_tv_aniso.py` sweeps tolerances in quarter decades and proxTV's iteration caps in half powers of two.

### Fixed

- Anisotropic TV used a warm-start dual without checking it, so an infeasible seed could certify a wrong point. For example, q₀ = x − mean(x) with the other blocks zero returned the constant image after 0 iterations as converged, with gap 0 and 57% error. A NaN dual left in the workspace by a NaN image made the next warm call run to `max_iter` with a NaN gap. Each fiber of a starting dual is now checked: its running sums must stay within γwₐ and end at 0, up to rounding. A fiber that fails is rebuilt from its clipped running sums. Feasible duals, including all duals from earlier calls, are used unchanged, so warm restarts stay bit-identical.

- Weighted ℓ1-ball projection with weights spanning many orders of magnitude could return outputs far larger than the input (z = [5.5e7, 2.4e70] for x = [11.0, 2.0], weights [1.8e-308, 7.7e-246] and radius 1e-300; found by fuzzing). - 1D TV: the Condat path falls back to the taut string after 3n + 1024 rescanned steps (was 16n + 1024 steps in total), which makes adversarial inputs such as ramps about 3.5× cheaper without affecting typical signals.
- 1D TV: the bound updates of Condat's algorithm are branch-free selects with a table of reciprocals, 25–35% faster on noisy signals (same arithmetic, so the same results).
- 1D TV: weighted problems now use Condat's direct algorithm, generalised to per-edge weights (radii precomputed per piece), with the same budgeted fallback to the taut string; `FP_TV1D_CONDAT` accepts weights. Weighted rows went from 1.4–2.8× slower than proxTV's weighted taut string to faster in most settings.
- 1D TV: radii that can never be active (above the dual bound j · (max x − min x)) are clamped, and when no edge can be active the result is the constant mean. Extreme weights or steps no longer cost accuracy: the residual stays within 10 n ε ‖x‖∞.
- 1D TV: the taut string stores its two chains as segments (length, rise, cached slope) in coordinates local to the current knot, an idea taken from proxTV's classic taut string. It is 17–26% faster and needs no compensated sums: the cumulative sum of the signal is never formed.
- Unweighted simplex and ℓ1-ball projections keep candidate values instead of indices (about 30% faster). The simplex also tests finiteness inside its pivot pass instead of a separate pass (a further 19%), and the ℓ1 ball and ℓ∞ prox reuse their ℓ1 norm as the test.
- 1D TV: bound updates are branch-free only in the first 8 samples of a segment; weighted rows read their radii directly when none can need clamping; operator construction makes one pass over the weights.
- Workspace scratch is no longer zero-filled, and the finiteness check is a branch-free pass: one-shot calls on large rows are noticeably faster.
- The version is defined once, in `CMakeLists.txt`; the Python package reads it from there.

### Fixed

- Weighted ℓ1-ball projection returned infinities for tiny weights (around 1e-279) because sums of squared weights underflowed (found by fuzzing). Weights are now normalised by their maximum, and ratios below 1e-100 are rejected.
- `fp_prox_conj` with σ = 0 on arrays with negative strides computed byte offsets in unsigned arithmetic (undefined behaviour, found by fuzzing).
- Static Windows builds marked API symbols `dllexport`.
- The taut string kept cumulative sums in plain doubles and missed the 10 n ε ‖x‖∞ accuracy bound on long rows; its chains now use local coordinates.
- A test assumed weighted isotonic regression is firmly nonexpansive in the Euclidean norm; it is so in the weighted norm, which the test now uses.
